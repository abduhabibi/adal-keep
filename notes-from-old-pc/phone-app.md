Since 2026-10-27 there is an Android app in `adal-phone/` (Capacitor 7.2, appId com.adalkeep.phone). Its start screen (www/app.js) asks the PC's 5-digit number (backend `pcNumber()` in mainPC.js, shown in Settings → Main PC), finds the PC with the native UDP plugin AdalDiscoveryPlugin.java (same ADAL_KEEP_DISCOVER_V1 broadcast as PCs), checks POST /api/mobile/pair, then opens the PC's own web UI (Wi-Fi URL first, Tailscale URL from anywhere). People pick their name on the Employees page as on a PC. The phone's live tab of a run is GET /automations/:id/screen + POST /automations/:id/input; calls ring via /api/tasks/calls polling.

**Why:** the user wants staff to do everything from their phones, shared through Xender, pairing only on the office Wi-Fi, working from anywhere through Tailscale.

**How to apply:** the release signing key is `~/.adal-keep/phone-release.jks` (+ `.properties` with its password) — never commit it, never regenerate it (a new key means phones must uninstall to update). Android SDK is in ~/Android/Sdk (user accepted the SDK license on 2026-10-27). Phones update themselves: on start the app asks its PC GET /api/mobile/app (src/phone-app/version.json) and installs /api/mobile/app.apk when newer (Android still shows one "Update" tap). To release: bump versionCode/versionName in adal-phone/android/app/build.gradle, run `adal-phone/build-apk.sh` (copies the signed APK + version.json into adal-keep-backend/src/phone-app, which IS committed), commit and push — PCs get it with their own auto-update. `adal-installer/build-installer.sh` copies that APK to the USB "5 - Phone app" (+ adb .bat + README, deps/platform-tools). Since 1.3 (2026-10-27) the APK also contains the Adal Keep pages themselves (adal-keep-frontend `npm run build:phone` → adal-phone/www, run by build-apk.sh; the launcher is public-phone/connect.html). When no PC answers, it opens them in cloud mode: src/cloud/adapter.js answers the API from Supabase keep_meta, which the main PC fills every minute (backend services/cloudSync.js), and phone changes go to keep_changes for the PC to replay. Tables: adal-admin/supabase/keep-sync.sql (the user must run it in the Supabase SQL Editor). Each phone gets its own Supabase user at pairing (keep_devices, removable in Settings → Main PC). Since 1.4: while the PC is on, cloud-mode phones relay every API call through Supabase keep_calls (PC startRelay in cloudSync.js answers on its local API, heartbeat keep_meta '/_pc'); X-Adal-Cloud makes onThisPC false. Automations still run only on the PC's Brave — the phone only sees and taps the run's tab. Since 1.8 (2026-10-27): phones work ONLY through Supabase (user's choice) — pairing from anywhere with the 5-digit PC number only, approved on the PC (RPC keep_request_join → PC popup "Yes, it's me" → keep_answer_join; user rejected passwords and number-only-without-approval); a live link over Supabase Realtime (backend services/liveChannel.js, frontend src/cloud/live.js, channel keep-<keep_secrets.live>, each message carries the phone JWT the PC verifies); updates from raw.githubusercontent release branch. Documents live encrypted in a private Telegram channel via @adalkeepbot (services/tgStore.js; TELEGRAM_BOT_TOKEN / TELEGRAM_STORAGE_CHAT in backend .env only, never committed). Related: [[usb-workflow]].

Update 2026-11-05: calls are Android notifications (AdalCalls, ReplyReceiver, inline reply and answer buttons). AdalWatchService plus MainActivity.keepPageRunning keep the page alive in the background. Swiping the app away stops it: that case would need Firebase push.
